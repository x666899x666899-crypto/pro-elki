# Инструкции для ИИ-агентов

Постоянные правила работы над проектом «ПРО ЁЛКИ». Владелец проекта — Сергей Михалёв, предприниматель. Объясняйте решения простым русским языком.

Бизнес-контекст: [docs/CONTEXT.md](docs/CONTEXT.md). Закупки: [docs/PURCHASES.md](docs/PURCHASES.md). Не перечитывайте весь проект, если хватает этих файлов и папки текущей задачи.

## Язык и тон

- Всегда отвечайте Сергею на русском языке, если он сам не попросил другой язык.
- Сначала говорите, что сделано и зачем. Технические термины поясняйте обычными словами.
- Перед крупным изменением коротко объясните, что собираетесь сделать.

## Границы работы

- Сначала смотрите существующие файлы и сохраняйте уже сделанное.
- Не создавайте вторую систему рядом с уже существующей.
- Не удаляйте работающий код без явного согласия Сергея.
- Разрабатывайте небольшими шагами, которые можно проверить.
- Не ставьте библиотеки, не подключайте сервисы и не пишите код магазина, пока Сергей не дал на это задание.
- Витрина — Tilda. Второй самописный сайт рядом не создавать.
- Не выдумывайте адрес, реквизиты ИП, розничные цены, остатки, домен, ключи и интеграции.
- Закупочная цена не равна розничной. ShopShop в документы «ПРО ЁЛКИ» не смешивать.
- Идеи из контекста помечать как идеи, пока Сергей их не подтвердил.
- Все компоненты должны оставаться совместимыми: сайт, боты, база, админка и интеграции читают одни и те же товары, цены, остатки и заказы.

## После каждого этапа

1. Обновите [PROGRESS.md](PROGRESS.md): что сделано, что в работе, что дальше.
2. Обновите общий [TASKS.md](TASKS.md) и `TASKS.md` затронутого компонента.
3. Важное техническое решение запишите в [docs/DECISIONS.md](docs/DECISIONS.md): дата, решение, почему, что из него следует.

## Секреты

В Markdown-файлы нельзя помещать пароли, токены ботов, ключи оплаты, доступы к таблицам и любые другие секреты. Если секрет уже попал в файл, не копируйте его в чат и в новые документы. Скажите Сергею, что секрет нужно убрать и заменить.

## Экономия контекста

Не читайте весь проект, если задача касается одного компонента. Открывайте README и TASKS этого компонента, общие правила из этого файла и только те документы, без которых задачу не решить.

Ориентиры:

| Задача | Что читать |
| --- | --- |
| Сайт | `website/`, при необходимости `docs/BUSINESS_LOGIC.md` |
| Telegram | `bots/telegram/` |
| MAX | `bots/max/` |
| База и таблицы | `database/`, `docs/ARCHITECTURE.md` |
| Оплата, доставка, обмен данными | `integrations/` |
| Админка | `admin/` |
| Общее устройство системы | `PROJECT.md`, `docs/` |

## Совместимость

- База — единственное место, где лежат товары, цены, остатки, клиенты и заказы.
- Сайт, боты и админка не заводят отдельные заказы и отдельные остатки.
- Акции и специальные предложения, которые действуют только на сайте, не подменяются отдельными правилами в ботах.
- Google Sheets может обмениваться данными с базой. Таблица не заменяет базу.

## Чего не делать без отдельного задания

- Не выбирать язык, фреймворк, хостинг, платёжную систему и службу доставки самостоятельно и не фиксировать это как окончательное решение.
- Не инициализировать git и не публиковать репозиторий.
- Не подключать Telegram, MAX, Google, оплату и доставку.
- Не заполнять каталог выдуманными товарами, выданными за реальные.
